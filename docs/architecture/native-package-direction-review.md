# 原生功能包方向复核

2026-09-10。依据用户补充的分析材料、`d4b317e` 已交付改动和当前本地并行开发代码。本文区分源码结论、已有截图验收和未完成的测量；本批暂不推送 PR。

## 结论

继续采用“宿主管窗口，官方包拥有功能内容，通过稳定值契约交换环境”的路线。当前需要完成运行时边界、功能对齐和资源成本验收，没有证据支持推翻为每格独立进程或把所有实例合并为一个 Controller。

同一 publisher/packageId、同一 content hash 的多个活跃格子复用 session 和已加载模块，但各实例有自己的 UI、图片、计时器与状态。不同 NativeAOT DLL 则存在各自的运行时和 GC 等成本；不能把“同包不重复加载”推导为“内存无需担心”。微软维护者说明了独立 AOT DLL 的 GC/线程成本；文中举例的 15 MB 不是 DeskBox 实测值。[运行时维护者说明](https://github.com/dotnet/runtime/discussions/102048)

成本应分为宿主及共享设施、已加载包的固定成本、实例增量。NativeAOT DLL 不支持卸载，关闭最后一个格子也不能等同于释放整包内存；包版本更新仍要求重启。[NativeAOT 官方说明](https://learn.microsoft.com/en-us/dotnet/core/deploying/native-aot/libraries)

## 契约原则

- 继续扩展现有 HostApi v4 的 JSON 环境快照；不新增另一套并行 Environment 通道，不跨原生边界传普通托管对象。
- 环境字段使用有效值与明确默认值。宿主全局策略限制是否允许运行，实例配置决定具体内容；缺字段的旧调用保持可用。
- 窗口材质、圆角、层级、窗口/胶囊动画由宿主负责；内容主题、文本颜色、内容材质和内容动画由包消费语义值后渲染。
- 后续功能包优先复用字段语义和源码级 SDK。不要引入必须与宿主同步升级的共享托管 UI DLL；颜色/字体角色可以继续提炼为语义 token，但不凭空增加产品设置。
- 同包的网络服务和缓存初始化按 session 共享，实例保持独立。图片按视口限制解码尺寸，加载和解码结果都要校验请求代次，失败保留上一个有效画面。

## 本批纠偏

复核发现，旧版本只在存在活跃 session 时检查 content hash，最后实例销毁后可能加载不同版本。本批改为进程级模块登记：原生 Load 成功即固定 identity/hash，ABI 检查或激活失败也保留；同 hash 可复用，不同 hash 必须重启。

在线图源不再依赖探针包内图片回退。旧缓存先导入包私有目录，多个实例等待同一个准备任务，随后才允许正常缓存刷新。缺失缓存项跳过，原缓存不改写；实际复制失败或取消不发布半成品 catalog。

## 发布前必须补的证据

用同一固定源码和 AOT 宿主依次测量：无功能包→首次加载 Glance→同包1/5个实例→关闭全部→同包重建→多个不同包。分别记录私有提交、工作集、线程数和图片场景，重复冷启动与稳定期样本；不把虚拟地址预留或工作集回落当作泄漏/回收结论。

继续完成 Direct/Store 分渠道、x64/ARM64、1.5.0 单跳升级和离线恢复、真实输入/拖放/合并/叠放验收。当前这些门槛尚不能标成通过；发布目标仍为 1.6.0。
