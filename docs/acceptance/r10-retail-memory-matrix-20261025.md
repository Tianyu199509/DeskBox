# 零售口径内存矩阵：1.5.9 vs 1.6.0 设置拆进程（2026-10-25）

回应问题：「拆分之后仅格子运行时内存没感觉更低」——用零售包把两版本 × 两场景钉死。

## 测量条件

- 1.5.9 = `C:\Program Files\DeskBox`（已安装零售，x64，就是线上终包）
- 1.6.0 = `feat/160-kickoff @ 865b0274` 零售 AOT 自包含发布（`.artifacts\aot-retail\win-x64\publish`，版本号未 bump 仍报 1.5.9）
- 两版本顺序跑、同一台机（1920×1080）、全新数据根走完新手引导（功能开关全关=纯文件格子默认集）、同等闲置时长（~9 分钟）后取数
- 隔离手段：1.5.9 无环境变量支持 → 临时改名真实数据目录（前后 136 文件 SHA256 全等证零触碰）；1.6.0 用 `DESKBOX_AOT_PREVIEW_DATA_ROOT`（注意：零售 AOT 认的是这个，不是 Debug 的 `DESKBOX_DEV_DATA_ROOT`——条件编译分叉）
- 指标：Private（commit，稳定口径）/ WS（受修剪时点影响仅参考）/ 线程数。场景②=打开设置逐节访问 5 个分节后关窗，等 90 秒

## 矩阵结果

| 场景 | 1.5.9 零售 | 1.6.0 零售 AOT |
|---|---|---|
| ① 冷启动·仅格子·稳态 | **Private 117.4MB** · 36 线程 | **Private 117.4MB** · 37 线程 |
| ② 开过设置→关→90s | 主进程 **Private 150.7MB（+33.3 永驻）** · 44 线程，窗=隐藏保留 | 主进程 **Private 118.4MB（+1.0）** · 37 线程，**宿主进程整体消失** |
| ② 打开期间设置 UI 成本 | 长在主进程里（树增量约 +33MB，与运行时共享） | 独立宿主进程 Private 107.6MB（自付一份 WinAppSDK 底座） |

## 结论

1. **「仅格子时没区别」被零售数据精确证实：117.4 = 117.4，分毫不差。** 这是设计使然——不开设置宿主就不存在，主进程代码路径与拆分前一致。拆分从来不以"从不打开设置"场景为目标。
2. **拆分的真实收益（开过设置的用户）**：1.5.9 关窗后 +33.3MB commit + 8 线程**永久驻留**（hide-and-reuse 保留整棵设置树，每次打开还会继续实例化更多分节）；1.6.0 关窗即宿主退出，主进程只 +1.0MB 回到基线。**开过设置的用户升级后稳态立省 ~32MB + 线程更少 + 设置崩溃不再连坐桌面。**
3. **如实披露的代价**：设置打开的瞬态，系统总占用略高于旧架构（宿主自付 ~70MB 级运行时底座+树，vs 旧架构只加树增量 33MB）——换来的是关窗归零与隔离。打开是瞬态，可接受。

## 计划修订（依据数据的判断）

原计划第二步的两个小优化（管道服务器惰性化+宿主退出触发回收）**建议不做**：零售数据显示关窗后残留仅 +1.0MB / +1 线程，收益已被数据抹平，不值得在发布分支上动代码。第三步激进项维持入库为债。
