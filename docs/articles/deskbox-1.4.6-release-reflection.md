# DeskBox 1.4.6 发布了，顺便聊聊这一路是怎么走过来的

今天，DeskBox 1.4.6 发出去了。

细心的老用户可能会注意到，上一个版本还是 1.4.5。这中间发生了什么，我在文章最后会讲。

先说发版的心情。说实话，按发布之前，我心里一点底都没有。做这个软件这么久，我最大的感受是，Windows 这件事，你永远不知道用户的电脑上正在发生什么。同一个功能，在我的机器上一切正常，换到另一台 Windows 10 上，可能就是一副我从未见过的样子。很多问题，只能等用的人遇到，告诉我现象，我再顺着日志一点点往回追。一个人能准备的机器和场景，终究有限。

所以趁着发版，我想把这一路的事捋一捋。DeskBox 是怎么来的，怎么走到今天，以及这段时间我重新想明白的一些事。

## 它的起点，是我想给自己找一个工具

我用了很多年腾讯桌面管家，同类软件也试了个遍。功能都够用，但界面大多停留在很多年前的 Windows 风格里。我一直很喜欢微软这几年的原生设计语言，想找一个看起来就像系统本身一部分的桌面整理工具。找了很久，没有。

那时候 AI 编程刚刚好用得起来。我的本职是产品经理，会一点 Python 和 SQL，C# 和 Rust 基本没碰过。我就想，要不自己试一次，让 AI 帮我把它写出来。

第一版很简单，只做一件事，把桌面上的文件收进格子里。但视觉就是我想象中的样子。我自己每天用，用着用着，觉得该有待办，该有剪贴板历史，后来又有了备忘录和音乐控制。功能就这样一点一点长了出来。

那段时间 DeskBox 没有产品计划，我的需求就是路线图。自己用得上，就值得做。

后来我在公众号随手写了一篇文章介绍它，五千多人看了，GitHub 上很快有了三百多个 Star。说实话，我当时完全不知道该怎么维护一个公开项目，只能有人提问就回答，出了问题就修。现在回头看，那是 DeskBox 第一次被迫营业。

## 一觉醒来，99+ 条未读

做到 1.4.2 的时候，有天晚上我顺手在 B 站传了一段演示视频。当晚录的，没有剪辑，讲话也不算利索，我只是想让人看看这个软件长什么样。

那段视频，后来有大约十四万播放。

Star 涨到一千六百多，Issues 超过一百个。有天早上醒来，未读消息 99+。高兴是真的，慌也是真的。有人在评论区反馈问题，有人在群里提建议，还有朋友专门整理了一份飞书文档，把发现的问题一条一条列了出来。

其中被提起最多的，是两件事。

第一件是性能。很多人说 DeskBox 占内存，用起来卡。这些反馈大多来自 Windows 10，也有一部分来自版本较早的 Windows 11。桌面工具是要常驻的，任务管理器里的数字一大，用户心里难免打鼓，常开它到底靠不靠谱。如果动画还不跟手，一个整理桌面的工具，反而成了每天要忍受的负担。

第二件更沉重。有用户卸载之后，发现桌面上的文件不见了，以为是被 DeskBox 删掉了。文件其实都在，只是被移进了收纳目录。但换位想一下，桌面上的东西突然找不到，用户感受到的就是文件丢了。对整理桌面的人来说，最怕的从来不是功能少，而是软件背着自己动文件。这种时候，一句数据都在是说服不了人的。软件怎么移动文件、去哪里找、卸载时会发生什么，这些都该在使用之前讲清楚。

还有一位用户，我印象很深。他平时不用 Microsoft Store，却为了支持 DeskBox，专门去商店付费下载了一次，然后卸载商店版，继续用 GitHub 版本。

商店版和 GitHub 版功能完全一致，没有任何独占内容。它存在的意义，是给愿意支持这个项目的人一个入口。DeskBox 消耗的是我下班后的全部时间，还有 AI 开发每个月实打实的成本。真的有人愿意用这种方式支持，我很感动。感动之后，更多的是自责，因为版本里还留着那么多我没来得及解决的问题。

那段时间，我慢慢确认了一件事。DeskBox 已经被一部分人真实地用起来了，它不再是我自己用着玩的软件。既然发了出去，用户的文件、时间和我得到的信任，就都要认真对待。

## 用的人多了，我反而开始做减法

用户多了，需求也多了。有人想要股票，有人需要新闻和视频，还有人提议做浏览器。客观说，每个需求单拿出来，都有它成立的场景。

但我一直在克制。

全部做进来，DeskBox 就会变成一个什么都能放的容器，安装体积、内存占用和设置复杂度一起上涨，最后连它自己是什么都说不清楚。一个桌面整理工具，不能靠堆功能来证明价值。

文件、待办、随记、音乐这些大多数人需要的，会一直留在本体里。更长尾的需求，我现在的想法是做插件市场，需要什么安装什么，不用的人不承担额外的体积和开销，社区也可以做自己的插件。这个方向还在思考阶段，没有时间表。

这也是把最初的想法重新确认了一遍。DeskBox 应该是轻的，少占资源，少打扰。你用它的时候它在，不用的时候，它安静待着。

当然，不是所有人都这么看。有人觉得这类软件没有价值，只是消耗 Token；有人觉得桌面整理做到收纳就够了，后面的功能都是负担；也有人只想要一个单纯的文件框。这些想法我都能理解，每个人期待的软件本来就不一样。做产品没办法让所有人满意，我只能保留自己的判断，只要有一群人愿意长期用它，这件事就值得继续。

## 这一个多月，我到底在改什么

这次更新，一大半时间花在性能上。

性能这件事，不同用户要的其实是相反的东西。有人盯着任务管理器，要求常驻内存尽可能低；有人要的是响应，格子一点就开，动画不能因为回收资源而卡顿。这两个目标天然冲突，想省内存就要积极回收，回收之后再次打开就要重新加载。

我没有替所有人做这个决定，而是把选择交了出来。1.4.6 提供了均衡、节省资源和自定义三种模式，缓存保留多少、闲置界面什么时候清理、临时窗口什么时候释放、哪些持续动画可以关闭，都可以自己调整。想压低占用就更积极地回收，在意流畅就多保留一些。

我也刻意没有在更新说明里写内存降低百分之多少这样的数字。不同电脑、不同格子数量，结果差异太大。给一个好看的数字很容易，给一个诚实的边界很难，我选择后者。

多显示器是另一块硬骨头。这个场景非常现实，很多用户在公司接扩展屏，回家用笔记本，排好的布局一换环境就全乱了，第二天回到公司又要重摆一遍。

只靠自适应，照顾不了所有组合。所以这一版加了布局快照，用户在某个屏幕环境里调整好一次，DeskBox 会记住这套组合，下次回到同样的环境，位置、尺寸、分组和胶囊都会还原。遇到全新的组合，才先做一次兜底的自适应。

[配图占位  性能与资源设置、多显示器布局恢复前后对比]

唤起方式也重新梳理了。除了默认的 F7，现在可以选双击 Ctrl、Alt+空格、Win+空格、单独按一下 Win，也可以双击桌面空白区域显示和隐藏格子。每个人的键盘习惯不一样，不该要求所有人记住同一种操作。

文件叠放把手动叠放和自动归组拆开了。想自动整理的用户继续用规则，只想把几个文件放在一起的用户，不会再被强制归组。叠放可以在格子里展开，也可以打开独立弹窗，图标大小和密度跟随格子设置，支持 Ctrl 加滚轮缩放，也会自动避开屏幕边缘。之前切换叠放时会闪现上一次内容的问题，这次也修掉了。

搜索接入了 Everything 的本机索引。DeskBox 不再维护自己的文件索引，同一个搜索框里，文件、随记、待办和设置都能找到。Everything 需要单独安装，DeskBox 只读取它的结果，不会捆绑。

还有一批小到不值得单独展开的改进。文件选中效果更接近 Windows 桌面，拖放可以跟随系统的复制和移动规则，Windows 10 的右键系统操作补齐了兼容，开机启动会等 Explorer 的桌面图标环境稳定之后再挂载桌面层，避免和系统恢复图标的位置互相干扰。

[配图占位  新快捷键、叠放弹窗与 Everything 搜索]

另外有两件事，需要提前说明。

GitHub 直发版切换到了 Native AOT，不再需要单独安装 .NET 10 运行时。Windows App Runtime 从 2.2 升级到了 2.4，如果电脑上还是旧运行时，使用直发安装包更新时会额外下载一次，少数情况下 Windows 会要求重启。完全离线的环境，需要先手动安装对应架构的 Runtime 2.4。

正常覆盖安装，设置、格子布局、待办、随记和收纳的文件都会保留。

[DeskBox 官方网站](https://deskbox.fun)

这些功能写出来只有几段，背后花掉的时间要远多于文字。我平时晚上八点下班，坐一小时公交到家，然后继续做 DeskBox，夜里一点到三点之间休息。这个状态持续了挺久，我老婆说我 Codex 中毒了。

我倒是没有想过放弃。被批评会难受，版本出问题会自责，但第二天打开电脑，还是要把能复现的问题复现出来，把逻辑重新理顺。

## 一个不会 C# 的产品经理，怎么写软件

DeskBox 从第一天起就是免费开源的。

理由说出来不复杂。我一直受益于那些免费开放的工具，其中不少具备足够的商业价值，作者依然选择把代码公开。我始终觉得这是很了不起的做事方式。轮到自己时，开源是很自然的选择。

这个软件确实是通过 AI 编程做出来的。我是产品经理，会一点 Python 和 SQL，C# 和 Rust 在这个项目之前，连语法都没有完整看过。大量代码由 AI 完成，是它让我脑子里的界面真正运行了起来。这一点，我很感谢它。

但代码能运行，只是一天工作的开始。我的大部分时间花在别的地方，这个按钮放在这里，用户会不会凭直觉点对；文件被移动之后，怎么让人放心；哪些需求做，哪些不做。这些判断 AI 替代不了，测试、回归和发布之后的责任，也只能由我来承担。

网上有一种声音，AI 做的产品，有什么资格开源。

我看到了。我的理解是，开源首先意味着任何人都可以检查 DeskBox 对你的电脑做了什么，你的文件和数据是怎样被处理的。项目现在有不少 Fork，有人持续提交问题、整理建议。如果以后真的做成插件模式，开源也能让更多人参与扩展。

AI 给了我把想法变成产品的能力。但用户是否愿意把它留在电脑上，取决于它能不能解决问题，以及出了问题之后，有没有人继续负责。

## 发出去，撤回来，再发出去

现在可以回答开头那个问题了，1.4.6 这个版本号，不在我的计划里。

它本来叫 1.4.5。发布当天，出现了一个真正严重的问题，在部分系统下，把 `.lnk` 快捷方式从一个格子拖到另一个位置，原快捷方式会被误删除，直接进入回收站。

发现的那一刻，我愣住了。前面才写过，用这个软件的人最怕的，就是软件背着自己动文件。结果我自己在这条线上摔了一跤。

原因后来查清楚了。拖放结束时，DeskBox 过早地告诉系统这是一次移动，系统便按照移动的规则去清理源位置，把还没搬运完成的快捷方式送进了回收站。修复之后，DeskBox 会等文件真正搬运完成，再向系统确认这次操作的结果。

所以 1.4.5 撤了下来，修复之后，以 1.4.6 重新发布。它现在写在更新说明的第一条。

这件事让我再次认清了独立开发的现实。Windows 的环境太复杂，显示器、系统版本、显卡驱动、权限设置，任何一项都可能改变最终表现。一个人、几台机器，覆盖不过来。很多问题，只能依靠遇到它的用户提供现象和日志，我一个一个去追。

1.4.6 经过了很多轮回归才发出来，但我现在依然会担心，某台我没有见过的电脑上，正在运行一个我同样没有见过的问题。

这份担心，大概以后每个版本都会在。

写这篇文章没有宏大的目的，只是版本发出去了，想把这段时间的事情讲一讲。如果你在用 DeskBox，更新到 1.4.6 就好；觉得哪里不顺手，随时告诉我；哪怕什么都不说，让它继续留在你的电脑上，对我也已经足够。

我会继续做下去，也尽量让它保持本来的样子，需要的时候在，不需要的时候，少打扰一点。
