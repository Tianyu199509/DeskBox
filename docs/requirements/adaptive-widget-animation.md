# 格子交互的自适应帧调度

适用范围是格子拖动、交互缩放、胶囊展开收缩、单格和批量显示隐藏。Win+D 的 Shell 行为继续由桌面层级策略处理。动画时长与轨迹使用单调时钟；调度次数不等于屏幕实际呈现次数。

## 调度与显示器

- `WidgetCompactAnimationCoordinator` 共享活动期间的时钟和胶囊边界批量提交；最后一个注册释放后停止时钟并释放升频租约。
- Win11 使用 XAML Rendering。Win10 优先后台 DwmFlush，仅允许一个待执行 UI tick；API 不可用、不能提供节奏或持续慢于活动显示器预算时，本轮改用刷新率派生的定时器，下轮重新尝试 DWM。每轮拥有独立身份，旧线程及旧队列回调不能进入新一轮。
- 定时器采用参与动画的最快显示器预算，不再固定在主屏或 8–16ms。直接拖动/缩放按自身所在显示器节奏合并输入；显隐窗口按静止位置的中心选择显示器，避免预先移到屏外后误选邻屏。
- `WidgetAnimationDisplayTiming` 在活动期间最多每 250ms 发起一次后台显示配置查询。主线程只消费完整快照；跨屏通过原生 monitor 归属识别。QueryDisplayConfig 保留刷新率分数，识别 Win11 DRR 的虚拟/物理模式，失败时回退 EnumDisplaySettings。
- DRR 物理高档位只是升频请求后的工作预算，不能据此宣称实际已跑满高档位。渲染回调和 DwmFlush 都不提供独立的逐显示器呈现保证。

## 输入、视觉与负载

- 缩放 PointerMoved 仅保存最新原生坐标，尺寸计算、吸附、参考线、锚点与窗口调整统一在帧回调处理。结束/丢失捕获先提交最新位置，再持久化。
- `WidgetAnimationFramePacingPolicy` 按时间截止提交，丢弃过期中间状态，不追赶补帧。实际工作成本持续增加时降低提交频率，成本下降后逐步恢复；每个动画独立重置，没有会话全局的降档记忆。
- 拖动/缩放只按显示周期合帧，不引入负载相关的额外跟手延迟。胶囊的成本采样包含共享 UI 和原生批量提交压力，不等于单个格子的独占成本。
- 胶囊透明度、内容位移和视觉缩放在 Win10/Win11 均由 Composition 执行；真实 HWND 边界、圆角和内容布局仍由应用管理。保留内容预布局、取消/反向和 watchdog，不再因达到 4 个并发就直接跳到终态。
- 批量显隐按窗口预算提交并去重相同像素位置；最终位置强制提交。DeferWindowPos 失败后不能结束失效事务，必须逐窗回退。原生提交失败单独报告，并通过宿主完成无动画显隐收尾，释放输入抑制和视觉活动状态。

## 诊断含义

- `WidgetBoundsInteraction`：指针样本、合并后的 UI 更新、输入到回调完成耗时与回调预算。
- `CompactAnimation`：UI ticks、成功 boundsUpdates、成功提交间隔、提交工作耗时及 outcome。
- `TrayAnimation`：UI 回调与成功原生位置提交分开统计。显示模式可在运行期间变化，初始刷新率不代表全程实际刷新率。

这些都是程序侧诊断。实际呈现和输入到光子延迟需要系统图形跟踪及物理设备观察。
